# Build, test, and lint petsc4py

Run these commands from `src/binding/petsc4py/` using the selected PETSc configuration.

## Build

petsc4py compiles a huge C source file generated by Cython, and optimizing that generated C code is
very slow. Always disable C optimization for a development build:

```console
$ CFLAGS="-O0" python setup.py build
```

## Test

The test runner automatically uses the Python build directory produced by `setup.py build`:

```console
$ python test/runtests.py
```

Select only tests relevant to the change with one or more `-k` substring patterns:

```console
$ python test/runtests.py -k test_name
$ python test/runtests.py -k test_name.class_name.method_name
```

Prefer a targeted `-k` run during development rather than the complete petsc4py test suite.

## Lint and documentation

Before concluding any petsc4py code change, run:

```console
$ make lint
```

All new petsc4py code must be documented. `make check-docs` is not a mandatory local completion
step; users can run it when an MR's `docs-review` job reports a problem.

Report when the selected PETSc configuration does not include the dependencies needed to build or
test the binding.
