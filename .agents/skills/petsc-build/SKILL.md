# Build PETSc and petsc4py

Read and follow `AGENTS.md` at the PETSc repository root. `arch-name` is a placeholder for the
architecture supplied by the user. Use its existing configuration; if it needs to change, follow
[petsc-configure](../petsc-configure/SKILL.md).

Run PETSc commands from the repository root. Build only what is relevant during iteration.

## Iterative build

Use the library target while editing:

```console
$ make -f makefile PETSC_ARCH=arch-name libs
```

The `libs` target is sufficient unless the task includes an external package built after PETSc.
The explicit `-f makefile` selects the library-build wrapper in `lib/petsc/conf/rules_doc.mk`,
which invokes the configured make with PETSc's parallelism and load limits. Keep this entry
point when those defaults are wanted; `make libs` can enter `gmakefile` directly with newer GNU
Make versions.

## Fortran bindings

When a public C header or API change adds, removes, or changes an interface represented in the
generated Fortran bindings, regenerate them before building only if the current configuration
enables them:

```console
$ make PETSC_ARCH=arch-name fortranbindings
```

## Complete the requested build

The `all` target also builds configured packages whose definitions under
`config/BuildSystem/config/packages/` set `self.builtafterpetsc = 1`:

```console
$ make PETSC_ARCH=arch-name all
```

A request to build the existing configuration includes its configured post-build packages. In
that case, run one final `all` build after editing, generation, and formatting without requesting
separate approval. Use `libs` when the requested scope is limited to PETSc libraries or the
prerequisites of a targeted test. Do not use `all` repeatedly during iteration unless the task
changes a post-build package.

## petsc4py

Before the first petsc4py build in a task, build the PETSc libraries with the `libs` command above
unless they have already been rebuilt from the current checkout in this task or the user confirms
that they are current. Rebuild after subsequent PETSc source changes that affect the bindings.

Run this command from `src/binding/petsc4py/` using the same architecture:

```console
$ PETSC_ARCH=arch-name CFLAGS='-O0' python setup.py build
```

The C source generated by Cython is large, and optimizing it is slow. Disable C optimization for
development builds unless the user requests an optimized build. Use the same Python interpreter
and environment for the build and subsequent tests.

## Diagnose failures

Inspect the first relevant compiler or linker error in the command output and the build log
under `arch-name/lib/petsc/conf/`. For petsc4py, also inspect the `setup.py build` output.
Distinguish a source error from missing configuration capabilities before changing configure
options. Report the failing command and the relevant error; do not switch architectures to
obtain a passing build.
